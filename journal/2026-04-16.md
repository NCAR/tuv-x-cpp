### CI fallout: tridiag solver tolerance

After push, `gcc (14, Release)` on macOS failed `TridiagSolveTest.DoublePrecision`:

```
Expected: (error) <= (TOL_DP), actual: 2.4040841983829188e-16 vs 2.2204460492503131e-16
```

Tolerance was set to exactly `std::numeric_limits<double>::epsilon()`. The test had been gated behind `TUVX_ENABLE_LAPACK`, so unconditioning it exposed latent flakiness — the averaged relative error landed 8% above ε on this one compiler/optimization combination.

Bumped both `TOL_SP` and `TOL_DP` to `10 * epsilon`. Still tight, but tolerant of compiler / FMA / optimization variation across the GCC/Clang/MSVC matrix. Pushed as a follow-up commit (`b35d03d`).
